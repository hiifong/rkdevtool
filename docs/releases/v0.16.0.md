## RKDevTool v0.16.0

**Release date:** 2026-10-07
**Full changelog:** https://github.com/hiifong/rkdevtool/compare/v0.15.0...v0.16.0

### New Features

- **Persistent forms:** Save download rows, enabled flags, storage types, addresses, names, image paths, selected row and force-by-address mode across page navigation and application restarts. The Advanced page Boot/firmware paths and Upgrade page firmware path are also saved independently.
- **Device partition import:** Read GPT or Rockchip parameter partitions directly through Rust/RockUSB and fill the download form with partition names, LBA addresses and the current storage type. Existing Loader/manual rows, image paths and enabled flags are preserved; importing the same table again does not duplicate matching entries.
- **Delete individual entries:** Remove a download configuration row using its delete button, automatically save the result and select an adjacent row when needed. Deletion is disabled while a task is running.

### Fixed

- **Large RKAF/RKFW firmware:** Recover offsets and sizes that wrap past the 32-bit header range, including partition images larger than 4 GiB. Stream extraction rather than loading the entire firmware into memory, and update `afptool-rs` to v1.2.5 for explicit header decoding and size recovery.
- **`parameter.txt` parsing:** Parse partition records line by line so trailing comments and independent `uuid:` records are not mistaken for additional partitions. Preserve custom partition names, grow partitions and partition UUIDs.
- **Partition reads after Loader download:** Use actual RockUSB LBA reads instead of rejecting a ready Loader because its USB descriptors still report Maskrom.

### Improved

- **Managed upgrade workspace:** Extract firmware under the application's cache directory, with a unique workspace and cleanup after each upgrade, instead of relying on the system temporary directory. This avoids putting extracted firmware on a small or quota-limited `/tmp` filesystem.
- **Partition table compatibility:** Support Rockchip's official PARM location at LBA `0x2000` and the legacy location at `0x20`, validate declared PARM payload lengths and bound GPT names to their standard UTF-16 name field.
- **Restored firmware metadata:** Re-read firmware and Loader versions when a saved path is restored. Clear outdated fields and discard stale asynchronous responses when paths change or the page is closed.
- **Download form layout:** Widen the partition name column so names such as `recovery` and `userdata` fit.
- **Documentation:** Update the bilingual README with partition import usage and remove partition table reads from the remaining official `upgrade_tool` dependencies.

### Validation

- Frontend type checking and production build passed with `npm run build`.
- Rust library tests: 73 passed; `cargo check` passed.
- Vue state/component checks covered persistence, clearing, deletion, repeated partition imports, malformed saved data, storage failures and asynchronous response ordering.
- Isolated browser checks with mocked Tauri responses covered partition import, navigation/reload persistence and preservation of the form after read failures.
